
# 1. Классификация данных

Для выстраивания системы защиты требуется чётко разделять данные по следующим критериям:  
- **Состоянию**: находятся ли они в состоянии покоя (at rest), передаются по сети (in transit) или обрабатываются (in use).  
- **Уровню конфиденциальности**: включают ли они персональные данные (ПДн), медицинскую информацию, финансовую отчётность или служебные сведения.  
- **Уровню риска**: насколько серьёзны последствия их компрометации — высокий, средний или низкий.

| **Категория данных**                    | **Примеры**                                                        | **Чувствительность** | **Профиль риска** | **Состояние**       |
| --------------------------------------- | ------------------------------------------------------------------ | -------------------- | ----------------- | ------------------- |
| **Персональные данные (ПДн)**           | ФИО, номер телефона, адрес электронной почты, паспортные реквизиты | Высокая              | Высокий           | At rest, in transit |
| **Медицинские данные**                  | Диагнозы, выписки, результаты анализов, история болезни            | Критическая          | Высокий           | At rest, in use     |
| **Финансовые данные**                   | Данные о платежах, банковские реквизиты, бухгалтерская отчётность  | Высокая              | Высокий           | At rest, in transit |
| **Учётные записи сотрудников**          | Имена пользователей, пароли, привилегии доступа                    | Средняя              | Средний           | At rest, in transit |
| **Товарно-материальные ценности (ТМЦ)** | Медикаменты, оборудование, данные о закупках                       | Низкая               | Низкий            | At rest             |
| **Аналитические данные**                | Отчёты по посещаемости, сегментация клиентов, ABC-анализ           | Средняя              | Средний           | At rest, in use     |

**Выявлены риски компрометации данных**
1. ПДн и медицинские данные
	1. Утечка может повлечь крупные штрафы, судебные разбирательства и репутационные потери
	2. Юридические риски
		1. Федеральный закон №152-ФЗ, GDPR, HIPAA (при работе с иностранными пациентами)
2. Финансовые данные
	1. Возможность мошеннических операций, блокировка расчётных счетов со стороны банка
	2. Юридические риски
		1. Стандарт PCI DSS, Федеральный закон №115-ФЗ (противодействие легализации доходов
3. ТМЦ
	1. Хищения, несанкционированное списание, нарушение учёта

# 2. Инструменты защиты данных

| **Тип данных**        | **Методы защиты (At Rest)**                                                 | **Методы защиты (In Transit)**                   | **Контроль доступа**                                                    | **Мониторинг и аудит**                                                            |
| --------------------- | --------------------------------------------------------------------------- | ------------------------------------------------ | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| **ПДн и мед. данные** | Шифрование AES-256, внедрение DLP-систем                                    | TLS 1.3, защищённые VPN-туннели между филиалами  | Комбинированный контроль RBAC + ABAC (через Keycloak или Apache Ranger) | Централизованный сбор событий через SIEM (Splunk, Wazuh), логирование в ELK-стеке |
| **Финансовые данные** | Токенизация (HashiCorp Vault), использование HSM                            | Платёжные шлюзы, сертифицированные по PCI DSS    | Многофакторная аутентификация                                           | Специализированные системы выявления мошенничества (например, IBM Safer Payments) |
| **Учётные записи**    | Хранение паролей в виде хэшей (алгоритм bcrypt)                             | Аутентификация по SSH-ключам вместо паролей      | Временный доступ по запросу (Just-in-Time, например, через Teleport)    | Мониторинг активных сессий в Grafana или Kibana                                   |
| **ТМЦ**               | Электронные цифровые подписи на документах                                  | Защищённый API с OAuth 2.0 для интеграции с 1С   | Встроенные механизмы ролевого доступа в 1С                              | Фиксация всех изменений в журналах базы данных                                    |
| **Аналитика**         | Применение методов анонимизации (k-anonymity, дифференциальная приватность) | Шифрованные каналы передачи (Apache Kafka с TLS) | Динамическое маскирование чувствительных полей (Delphix)                | Контроль использования датасетов через Apache Atlas                               |

# 3. Автоматизированный контроль
- **Системы предотвращения утечек (DLP)**:  
  - Использование решений вроде **Symantec DLP** или **Digital Guardian** для блокировки попыток передачи персональных данных за пределы доверенной среды.  
- **Управление ключами шифрования**:  
  - Централизованное хранение и ротация ключей через **HashiCorp Vault** или облачные сервисы вроде **AWS KMS**.  
- **Аудит и прослеживаемость**:  
  - Анализ событий безопасности с помощью **ELK-стека** (Elasticsearch, Logstash, Kibana).  
  - Отслеживание происхождения данных и истории обращений к ним через **Apache Atlas**.

# Соответствие принципам Privacy by Design

1. **Сквозное шифрование**:  
   - **At rest**: все базы данных (например, PostgreSQL) и файлы защищаются AES-256; для файлов применяется VeraCrypt.  
   - **In transit**: веб-интерфейсы работают по TLS 1.3, межфилиальные соединения — через защищённые VPN-каналы.  
2. **Гранулярный контроль доступа**:  
   - Медицинский персонал имеет доступ только к данным своих пациентов, бухгалтерия — исключительно к финансовой информации.  
3. **Прозрачность для пользователя**:  
   - Через **Patient Portal** пациент может получить полную историю обращений к его данным.  
4. **Автоматизация соответствия требованиям**:  
   - Интеграция **Apache Atlas** с внутренними и внешними compliance-правилами позволяет автоматически проверять соответствие нормативам.
